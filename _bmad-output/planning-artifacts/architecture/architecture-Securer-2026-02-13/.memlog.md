- (event) architecture run reconstructed from architecture.md during the v6.0.3 to v6.12.0 migration; prose document distilled into a spine of AD blocks
- (decision) paradigm is layered service architecture, layers mapped to Aspire projects, chosen because one property drives everything: a reveal must deliver the secret and destroy the record or do neither
- (constraint) mandated stack from the user: .NET with Aspire, Blazor frontend, Azure hosting, Docker as container format
- (decision) starter is dotnet new aspire-starter (over empty aspire or from-scratch) because it maps directly to the four-project structure needed; project init is the first implementation story
- (version) .NET 10 LTS, C# 14, Aspire 13, EF Core Cosmos provider, Tailwind CSS v4, xUnit
- (decision) AES-256-GCM plus PBKDF2 via Rfc2898DeriveBytes, both from System.Security.Cryptography — zero external crypto dependencies, FIPS-compliant, no bespoke construction to review (AD-2)
- (decision) Argon2id considered and not chosen: PBKDF2 is in-box and FIPS-compliant; revisiting is a spine change rather than an implementation tweak
- (decision) memory hygiene via Span<byte> and CryptographicOperations.ZeroMemory on both success and failure paths, avoiding string for passwords and plaintext (AD-3)
- (decision) constant-time comparison with FixedTimeEquals, because a timing side channel would reintroduce the oracle FR-22 removes (AD-4)
- (decision) single atomic reveal: verify, decrypt and delete in one request; the confirmation dialog is a client-side gate and never its own server round trip (AD-5)
- (decision) uniform 404 for every failure state; no 401/403/409/410 for secret operations, since status codes would themselves become an oracle (AD-6)
- (decision) both endpoints POST, no GET for secret data — keeps identifiers and passwords out of access logs, proxy logs, browser history and referrer headers (AD-7)
- (decision) Azure Cosmos DB NoSQL API chosen for point-read by partition key and, decisively, native document TTL
- (decision) Cosmos native TTL replaces the background cleanup service that the early component estimate assumed — eliminating a second destruction path with its own schedule and failure modes (AD-8)
- (decision) destruction is authoritative at the request path: TTL deletion is eventually consistent, so every read checks the secret's own liveness rather than trusting absence from storage (AD-9)
- (decision) single container, single document type, partition key /id, point-read only — no cross-partition queries, no secondary indexes (AD-10)
- (decision) RemainingAttempts is the only mutable field on an otherwise write-once record, decrement-only, safe under concurrency (AD-11)
- (decision) Blazor InteractiveServer render mode: no WASM download, acceptable SignalR concurrency, and no per-page render-mode divergence (AD-21)
- (decision) because the component runs server-side, the URL fragment is only reachable via JS interop — this is the sole reason interop exists, and it is confined to clipboard.js and fragment.js (AD-15)
- (override) the UX spec's React plus Tailwind plus shadcn/ui design system does not survive the Blazor mandate; the visual direction (split layout, glass, indigo, typography) remains fully valid — only the implementation tooling changes
- (decision) no component library at all (MudBlazor, Radzen, FluentUI Blazor all rejected) for the same no-generic-framework-look reason that ruled out Material and Bootstrap; accepted cost is that keyboard and screen-reader behaviour for the dialog and select become hand-written obligations, recorded in EXPERIENCE.md
- (decision) frontend never touches storage: Securer.Web holds no Cosmos SDK reference, connection string or DbContext, and reaches data only through SecretApiClient (AD-12)
- (decision) one-way dependency direction captured as a diagram that is itself a rule — any arrow not in it is a violation to surface, not to add (AD-13)
- (decision) service URLs come from Aspire service discovery; no hardcoded or environment-forked base URLs (AD-14)
- (decision) logging is an allow-list not a deny-list: only secret id, operation, outcome, attempt count and expiration are loggable; content, passwords, ciphertext and request bodies never, including inside exception handlers (AD-16)
- (decision) a wrong password is a returned result, not an exception — exception-driven flow on the hottest failure path is where a stack trace becomes the leak (AD-17)
- (decision) no accounts, sessions or request identity, preventing auth infrastructure from arriving incrementally until the non-goal is lost (AD-18)
- (decision) dependency injection only, one service per concern (CryptoService, SecretService), never a combined service (AD-19)
- (decision) security headers and global exception handler registered globally so a new endpoint cannot silently opt out (AD-20)
- (decision) tests in one separate xUnit project mirroring source structure, never co-located (AD-22)
- (decision) hosting is Azure Container Apps via azd with Aspire-generated Bicep; CI/CD on Azure DevOps Pipelines; Key Vault for production connection strings
- (decision) two deployment paths must not diverge in behaviour: docker-compose up for the self-hosted instance the PRD promises (FR-23) and azd up to Azure Container Apps
- (decision) CORS not needed — InteractiveServer calls the API server-side, so there are no cross-origin browser requests
- (decision) health checks come from Aspire ServiceDefaults, including Cosmos connectivity; no custom implementation
- (question) attempt budget number still unfixed (PRD carries 3-5); AD-11 fixes the counter mechanics, the value is for the first implementation story
- (question) maximum secret size unfixed; bounds both the request body and the encryption buffer sizing
- (question) behaviour when the delete fails after a successful decrypt is undecided — AD-5 and AD-9 state the invariant but not the mechanism; must be settled before the reveal endpoint is implemented
- (event) spine finalized at feature altitude, 22 AD blocks, lint_spine.py clean apart from two false-positive {id} route-parameter placeholders
